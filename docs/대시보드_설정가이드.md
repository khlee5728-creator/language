# 연습문제 대시보드 설정 가이드 (Supabase)

학생이 덱의 객관식을 풀면 첫 시도가 Supabase에 기록되고, 강사는 `dashboard.html`에서 확인한다.
데이터는 Supabase 프로젝트에만 저장되며 공개 저장소에는 anon key(공개용)만 들어간다.

## 구성 요소

| 파일 | 역할 |
|---|---|
| `supabase/schema.sql` | 표·RLS 정책·실시간·집계 뷰. SQL Editor에 붙여넣고 1회 실행 |
| `slides/assets/quiz-config.js` | URL·anon key·학기·학번 필수 여부 (학기마다 `SEMESTER`만 변경) |
| `slides/assets/slides-quiz.js` (v5) | 덱 시작 시 학번 1회 입력 → 선택 즉시 INSERT, 실패분 재전송 큐, 학번 배지 |
| `slides/assets/quiz-bank.js` | 문항 은행(덱에서 자동 생성). 대시보드가 문항 텍스트·정답을 여기서 읽음 |
| `dashboard.html` | 강사 전용 화면. 이메일·비밀번호 로그인 → Overview / Questions / Students / Live |

## 설정 순서 (약 10분)

1. **프로젝트 생성** — supabase.com → New project (리전 Northeast Asia 권장).
2. **스키마 실행** — SQL Editor → `supabase/schema.sql` 전체 붙여넣기 → Run.
   마지막 줄 결과가 `ok | 1`이면 성공. 강사 이메일을 바꾸려면 파일 상단 `instructors` INSERT 값을 수정.
3. **키 복사** — Project Settings → API → `Project URL`, `anon public` key.
   `slides/assets/quiz-config.js`의 `SUPABASE_URL`, `SUPABASE_ANON_KEY`에 입력. (`service_role` 키는 절대 넣지 않는다.)
4. **강사 계정 생성** — Authentication → Users → **Add user** → *Create new user*
   - Email: `instructors` 표에 넣은 이메일(기본 khlee5728@gmail.com), Password: 원하는 비밀번호
   - **Auto Confirm User** 체크(메일 인증 생략) → Create user
   - Authentication → Providers → Email 이 켜져 있어야 한다(기본값). 매직링크·Site URL 설정은 필요 없다.
5. **배포** — 커밋·푸시 후 `dashboard.html` 접속 → 이메일·비밀번호 입력.
   `instructors` 표에 없는 이메일은 로그인은 되지만 데이터가 비어 보인다(RLS).
   비밀번호 변경은 Authentication → Users → 해당 사용자 → *Reset password* 또는 *Send password recovery*.

## 학생 쪽 동작

- 덱을 열면 첫 화면에서 학번 입력창이 한 번 뜬다(브라우저에 저장, 이름 미수집).
- `REQUIRE_ID: false`(기본)면 "학번 없이 계속"으로 익명(`anon-xxxx`) 기록 가능. 익명은 대시보드 하단에 묶여 표시된다.
- 학번을 바꾸려면 브라우저 콘솔에서 `localStorage.removeItem('tel_student_id')`.
- 문항당 첫 시도만 저장된다(같은 학번·주차·문항 중복은 서버가 무시).

## 대시보드 화면

- **Overview**: 주차별 응시 학생·응답 수·완료율(전 문항 응답 비율)·정답률·최저 정답 문항.
- **Questions**: 선택 주차의 문항별 정답률과 선택지 분포(정답 선택지 녹색). 시험 출제 난이도 참고용.
- **Students**: 학번 × 주차 매트릭스(정답/응답 수). 전 문항 응답 시 녹색.
  **Edit roster**로 수강생 학번을 붙여넣어 두면 명단 학생이 항상 표에 나타나고, 응답 없는 주차는 ✗로 표시되며
  상단에 "명단 N명 중 W주 응시 M명 · 미응시 학번"이 요약된다. 명단 밖 학번(오타 등)은 '명단 외'로 중간에, 익명은 하단에 묶인다.

- **Live**: 선택 주차의 응답이 도착하는 즉시 반영 + 최근 응답 스트림. 수업 중 문제 풀이 시 화면에 띄운다.
- **Export CSV**: 현재 학기 전체 원자료.
- 미리보기: `dashboard.html?demo=1` (가짜 데이터, 네트워크 없음).

## 학번 입력 유도(필수 아님)

- 덱을 열면 첫 화면에서 학번 입력창이 한 번 뜬다(연습문제가 있는 덱만). 건너뛰면 익명으로 기록되고, 학번이 없는 채 문항을 클릭하면 그때 다시 묻는다.
- 강사가 수업용으로 덱을 열 때도 한 번 뜬다 — 건너뛰기(또는 아무 값)로 닫으면 그 브라우저에서는 다시 묻지 않는다.
- 연습문제 슬라이드 좌하단에 상태 배지: 학번이 있으면 `STUDENT ID 2026123 · 변경`, 없으면 붉은 글씨 "미입력 — 풀이 여부가 확인되지 않습니다 · 학번 입력".
- 나중에 학번을 입력하면 그 브라우저에서 익명으로 푼 답이 학번으로 함께 재전송된다(익명 행은 남지만 대시보드 하단 묶음이라 무시해도 됨).

## 연결 테스트 후 정리

연결 검증 시 `semester = 'test'`로 시험 행(test-0001~0003)을 넣었다. SQL Editor에서 한 번 지운다:

```sql
delete from public.quiz_responses where semester = 'test';
```

기술 메모: PostgREST의 `on_conflict` 업서트(ignore-duplicates)는 anon INSERT 정책과 충돌해 401이 난다.
클라이언트는 행 단위 일반 INSERT를 쓰고, 중복(409)은 "이미 기록됨"으로 처리한다.

## 학기 전환

`quiz-config.js`의 `SEMESTER`를 `'2027-1'`처럼 바꾸면 새 학기 데이터가 분리 저장되고, 대시보드 Semester 선택으로 과거 학기도 볼 수 있다.

## 문항을 추가·삭제했을 때

문항 ID(`data-qid`)는 덱 내 순서로 부여된다. 중간에 문항을 끼워 넣으면 뒤 번호가 밀리므로,
학기 중에는 **끝에 추가**하거나 기존 ID를 유지한다. 변경 후 scratchpad `quiz_patch.py`로 `quiz-bank.js`를 재생성한다.

## 제약

- 정답이 덱 HTML에 있어 학생이 소스를 보면 알 수 있다 — 형성평가·복습 용도. 성적 반영 시 서버 채점으로 전환 필요.
- 학번은 자기 신고. 대리 응답은 막지 못한다.
- 강의계획서에 "연습문제 응답은 학습 확인용으로 기록됨(학번만 수집)"을 명시할 것.
